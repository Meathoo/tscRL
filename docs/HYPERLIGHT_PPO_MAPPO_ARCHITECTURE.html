HyperLight PPO / MAPPO 詳細架構

本文件整理目前專案中 hyperlight_ppo 與 hyperlight_mappo 的實作架構。兩者共用同一個 agent 類別骨架與 PPO 更新流程，差異主要由設定檔控制： PPO 使用 local value input，MAPPO-style 版本打開 centralized critic，讓 value network 在訓練時看到全域交通摘要。

on-policy rollout GAE PPO clipped objective hypernetwork-generated actor hypernetwork-generated value centralized critic for MAPPO

1. 總覽

HyperLightPPOAgent 是一個 HyperMARL-style 的 PPO/IPPO 交通號誌控制器。 它不是為每個 intersection 建立獨立 PyTorch policy module，而是先為每個 agent 準備一個 meta embedding，再透過 hypernetwork 產生該 agent 的 actor 與 value network 參數。

HyperLightMAPPOAgent 目前是 HyperLightPPOAgent 的空子類別，只負責註冊 hyperlight_mappo 這個 model name。實際 MAPPO-style 行為由 configs/tsc/hyperlight_mappo.yml 覆寫設定完成，最重要的是 centralized_critic: True。

World / TSCEnv CityFlow 或 SUMO world 產生 lane feature、phase 與 reward。
State Builder observation 正規化、padding，再串接 current phase。
Agent Meta one-hot 或 learned embedding，shape 為 [B, N, E]。
Hypernetworks 產生 actor theta 與 value theta，每個 intersection 一組參數。
PPO Update rollout buffer、GAE、clipped policy loss、value loss、entropy bonus。
目前程式碼的核心特徵： actor 永遠只吃 local state，所以執行時是 decentralized execution； MAPPO-style 的集中化只發生在 value input，也就是 centralized training 的 critic/value 分支。

2. 來源檔案與註冊

目前 PPO/MAPPO 分支主要由以下檔案組成：

agent/hyperlight_ppo.py 核心 agent。定義 HyperLightPPOAgent 與 HyperLightMAPPOAgent。
agent/actor.py 定義 frozen template actor BaseActor，供 hypernetwork 取得參數 layout。
agent/hypernetwork.py 提供 LinearHyperNetwork、MLPHyperNetwork 與 build_hypernetwork()。
configs/tsc/hyperlight_ppo.yml PPO 預設設定。local critic、rollout length、PPO loss 超參數都在這裡。
configs/tsc/hyperlight_mappo.yml 繼承 PPO 設定，只覆寫 model name 與 centralized critic 設定。
trainer/tsc_trainer.py 呼叫 get_action()、remember()、train() 的 LibSignal TSC 訓練迴圈。

Model Registry

@Registry.register_model('hyperlight_ppo')
class HyperLightPPOAgent(RLAgent):
    ...

@Registry.register_model('hyperlight_mappo')
class HyperLightMAPPOAgent(HyperLightPPOAgent):
    pass

agent/__init__.py 會 import 這兩個類別，因此執行 run.py 時， 只要命令列指定 --agent hyperlight_ppo 或 --agent hyperlight_mappo， registry 就能建立正確 agent。

命名說明： 目前 hyperlight_mappo 是 MAPPO-style，而不是另一套獨立演算法實作。 它沿用 PPO rollout、GAE 與 clipped objective，只把 value 分支改成 centralized critic。

4. LibSignal 執行流程

TSCTrainer.create_agents() 會先建立一個 agent，該 agent 的 sub_agents = len(world.intersections)，因此在一般 TSC 設定下， 一個 HyperLightPPOAgent 實例會控制整張 road network 的所有 intersections。

reset env.reset() 後 agent 重建 generators 與 cache。
observe get_ob() 與 get_phase() 取得 [N, O] 和 [N]。
act get_action() 回傳每個 intersection 的 phase index。
step env.step(actions.flatten()) 推進 action_interval 秒。
learn remember() 存 rollout，train() 滿 rollout 後更新。

訓練迴圈細節

  1. 每個 episode 開始時，metric.clear()、env.reset()、agent.reset()。
  2. 每隔 action_interval 才決策一次，預設為 10 simulator steps。
  3. learning_start: -1，所以從第一個 decision 開始就會使用 policy，而不是先 random warmup。
  4. get_action() 會同步 cache action probability 與 value，get_action_prob() 隨後取出同一份 old policy probability。
  5. remember() 將 transition 放進 on-policy rollout buffer。
  6. update_model_rate: 1 代表 trainer 每個 decision 都呼叫 train()，但 agent 只有累積到 ppo_rollout_steps 才真的更新。
per decision:
  phase_t = agent.get_phase()
  action_t = agent.get_action(obs_t, phase_t)
  old_prob_t = agent.get_action_prob(obs_t, phase_t)
  obs_{t+1}, reward_t = env.step(action_t) repeated action_interval times
  phase_{t+1} = agent.get_phase()
  agent.remember(obs_t, phase_t, action_t, old_prob_t, reward_t, obs_{t+1}, phase_{t+1}, done)
  loss = agent.train()

5. State / Action / Reward

本節使用以下符號：

符號 意義 目前來源
N intersection / sub-agent 數量 len(world.intersections)
A 最大 phase 數量，也是 actor output dim max(len(inter.phases))
O padding 後的 observation length 所有 intersection 的 LaneVehicleGenerator.ob_length 最大值
S final state dim O + A，當 phase=True 且 one_hot=True
B batch 或 rollout step 數 train 時的 sampled rollout/minibatch length

Observation

get_ob() 對每個 intersection 建立 LaneVehicleGenerator， 預設 features 是 lane_count 與 lane_waiting_count。 產生的數值會除以 vehicle_max，預設 50。如果不同 intersection 的 lane 數不同， 則短的 observation 會 zero-pad，長的會 truncate 到 O。 

raw_obs_i = LaneVehicleGenerator(...).generate()
obs_i = raw_obs_i / vehicle_max
obs_i = pad_or_truncate(obs_i, O)
obs shape = [N, O]

Phase Feature

get_phase() 使用 IntersectionPhaseGenerator 讀取 current phase， 並把 phase index clamp 在該 intersection 合法 phase 範圍內。預設 one_hot=True， 因此 phase 會轉成長度 A 的 one-hot 向量，再接到 observation 後面。 

phase_onehot shape = [N, A]
state = concat(obs, phase_onehot, dim=-1)
state shape = [N, S]

Action Mask

因為不同 intersection 的 phase 數可能不同，agent 會建立 action_mask，shape 為 [N, A]。有效 phase 是 True，無效 phase 是 False。 policy logits 會對無效 phase 填入 -1e9，sample 時也只會在合法範圍內抽樣。 

logits = logits.masked_fill(~action_mask[None, :, :], -1e9)
action_i ∈ {0, ..., phase_lengths[i] - 1}

Reward

reward generator 預設讀取 lane_waiting_count，average='all'， 並設定 negative=True。因此每個 intersection 的 reward 是負的平均等待車輛數。 進入 PPO tensor 時會再乘上 reward_scale，目前預設為 0.05。

6. Agent Embedding 與 Meta Input

PPO/MAPPO 分支沒有使用 hyperlight.py 裡的 positional encoding 與 system mu。 目前這條分支採用較接近公開 HyperMARL PPO/IPPO/MAPPO 程式的 agent embedding conditioning。

模式 設定 meta dim 是否可訓練
one-hot agent_embedding_mode: one_hot N 否，使用 torch.eye(N)
learned agent_embedding_mode: learned agent_embedding_dim 是，nn.Parameter[N, E]，orthogonal init 
agent_embeddings shape = [N, E]
meta = agent_embeddings[None, :, :].expand(B, N, E)
meta shape = [B, N, E]
目前預設： agent_embedding_mode: one_hot。這代表 hypernetwork input dim 會隨地圖 intersection 數量 N 改變，對同一張地圖訓練很直接；若要跨不同規模地圖重用模型，通常需要額外設計 embedding 或 meta 描述。

7. Actor Hypernetwork

actor 使用 BaseActor 作為 template，但 BaseActor 的參數本身全部 requires_grad = False。它的主要用途是提供 layer name、shape 與 flattened parameter layout。 真正訓練的是 actor_hypernet，它根據每個 agent 的 meta embedding 產生 actor 權重。

Template Actor

BaseActor(S, H1, H2, A) ↓ layout only fc1, fc2, fc3 weights/biases

Actor Hypernetwork

meta_i [E] ↓ theta_pi_i [P_actor]

Generated Policy

state_i [S] ↓ masked logits_i [A]

BaseActor 結構

state_i [S]
  -> Linear(S, actor_hidden1)
  -> ReLU
  -> Linear(actor_hidden1, actor_hidden2)
  -> ReLU
  -> Linear(actor_hidden2, A)
  -> logits_i [A]

Actor Parameter Dim

flattened actor 參數總長度為：

P_actor = H1*S + H1 + H2*H1 + H2 + A*H2 + A

預設 actor_hidden1=64、actor_hidden2=64。S 與 A 由 road network 與 phase 設定決定。

Forward 實作

_actor_forward(state_tensor, theta) 會把 flattened theta 依照 actor_layout 切成每層 weight/bias，然後用 torch.einsum 做 batched per-agent linear layer。 

state_tensor shape = [B, N, S]
actor_theta shape = [B, N, P_actor]
logits shape = [B, N, A]

8. Value Hypernetwork

value network 也不是固定 module，而是由 value_hypernet 產生每個 agent 的 value network 參數。 這個分支是 hyperlight_ppo 與 hyperlight_mappo 的主要架構差異。

Local Value Input: hyperlight_ppo

centralized_critic = False
value_input_i = state_i
value_input_dim = S

Pooled Centralized Value Input: hyperlight_mappo 預設

pooled mode 會先從所有 intersections 的 state 計算四種全域統計：mean、std、max、min。 每個 agent 的 value network 都會收到自己的 local state，加上同一份 global context。 

global_mean = mean(states, dim=N)  # [B, 1, S]
global_std  = std(states, dim=N)   # [B, 1, S]
global_max  = max(states, dim=N)   # [B, 1, S]
global_min  = min(states, dim=N)   # [B, 1, S]

global_context = concat(mean, std, max, min)  # [B, 1, 4S]
global_context = expand(global_context, N)    # [B, N, 4S]
value_input_i = concat(state_i, global_context_i)
value_input_dim = 5S

Concat Centralized Value Input: 可選

centralized_critic_mode = concat
global_state = reshape(states, [B, N*S])
value_input_i = global_state
value_input_dim = N*S
大型路網建議使用 pooled： concat 會讓 value input dim 隨 N*S 線性放大， 進而讓 hypernetwork 需要產生更大的 value network 參數，對大地圖可能很重。

Value Network Layout

value network dims 由 [value_input_dim] + value_hidden + [1] 組成。 PPO 預設 value_hidden: [64, 64]；MAPPO 覆寫為 [128, 64]。 

value_input shape = [B, N, value_input_dim]
value_theta shape = [B, N, P_value]
values shape = [B, N]

9. PPO / GAE 更新流程

這條分支是 on-policy PPO。transition 先進入 rollout_buffer， 當 _transitions_since_update >= ppo_rollout_steps 時， train() 會取出整段 rollout、清空 buffer，接著計算 GAE 與 PPO loss。

Rollout Buffer 內容

(
  state,        # [N, S]
  next_state,   # [N, S]
  actions,      # [N]
  rewards,      # [N]
  done_arr,     # [N]
  old_log_prob, # [N]
  old_value     # [N]
)

GAE

_compute_gae() 使用 rollout 中保存的 old_values， 並用最後一個 next_state 估計 bootstrap value。

delta_t = r_t + gamma * V(s_{t+1}) * (1 - done_t) - V(s_t)
A_t = delta_t + gamma * lambda * (1 - done_t) * A_{t+1}
returns_t = A_t + V(s_t)

預設會 normalize advantages： (advantages - mean) / (std + 1e-8)。

PPO Loss

對每個 minibatch，agent 重新跑一次 current policy/value，取得新的 log probability 與 value。

ratio = exp(new_log_prob - old_log_prob)
policy_loss = -mean(min(ratio * A, clip(ratio, 1-eps, 1+eps) * A))
value_loss = 0.5 * clipped_or_plain_mse(value, returns)
loss = policy_loss + value_coef * value_loss - entropy_coef * entropy

Minibatch 切法

buffer 裡的主要時間維度是 decision step。程式會先決定每個 minibatch 包含幾個 rollout steps： 

step_batch_size = min(num_steps, ppo_minibatch_size // N)

這樣可讓展開後的總樣本數約等於 ppo_minibatch_size，也就是 step_batch_size * N 個 agent-time samples。

Optimizer

optimizer 只更新下列參數：

  • actor_hypernet.parameters()
  • value_hypernet.parameters()
  • 若 agent_embedding_mode=learned，也更新 agent_embeddings

BaseActor 不更新，因為它只是 layout template。每次 backward 後會使用 clip_grad_norm_，預設 grad_clip=0.5。

11. Checkpoint 儲存與載入

save_model(e) 會在 logger path 的 model 資料夾下存成 {e}_{rank}.pt。目前 payload 包含：

  • actor_hypernet.state_dict()
  • value_hypernet.state_dict()
  • optimizer.state_dict()
  • embedding_mode
  • agent_embeddings 的 tensor copy

load_model(e) 會恢復 actor/value hypernet，若目前是 learned embedding 且 checkpoint 有 agent_embeddings，也會把 embedding 載回目前 device。optimizer state 若存在也會載入。

12. 實作注意事項

MAPPO 的 centralized critic 只影響 value

_policy_value() 中 actor logits 一律由 local state 產生。 centralized_critic 只改變 _value_input() 的輸入。

Action space 取最大 phase 數

A = max(phase_lengths)，較少 phase 的 intersection 靠 action_mask 避免選到非法 action。

rollout buffer 是 on-policy 用法

雖然名稱也指派給 replay_buffer，但 train() 會在每次 PPO 更新前取出並清空整段 rollout。

old log probability 來自 cache

get_action() 先 cache probability，隨後 get_action_prob() 取回，確保 remember() 保存的是 action 當下的 old policy probability。

target network 無作用

update_target_network() 在 PPO/MAPPO 分支是 pass。 trainer 仍會照通用流程呼叫，但不會更新任何 target module。

大型地圖 value input 要留意

centralized_critic_mode: concat 的 value_input_dim = N*S。 若 N 很大，建議維持目前預設 pooled。
