# Native PPO / MAPPO Baselines

This project now has non-hypernetwork PPO/MAPPO baselines for TSC:

- `ppo`
- `mappo`
- aliases: `native_ppo`, `native_mappo`, `ppo_native`, `mappo_native`

## Relation To HyperLight PPO / MAPPO

`hyperlight_ppo` and `hyperlight_mappo` use the same PPO/GAE training objective,
but actor/value parameters are generated by agent-conditioned hypernetworks.

`ppo` and `mappo` use ordinary shared MLPs:

```text
actor: shared MLP(local_state_i, optional_agent_id_i) -> phase logits_i
value: shared MLP(value_input_i, optional_agent_id_i) -> V_i
```

There is no hypernetwork and no RF initialization in native PPO/MAPPO.

## PPO vs MAPPO

PPO:

```yaml
centralized_critic: False
```

The value network receives each agent's local state.

MAPPO:

```yaml
centralized_critic: True
centralized_critic_mode: pooled
```

The value network receives local state plus global traffic summary statistics.
`concat` is also available, but `pooled` is the safer TSC default.

## Agent ID

By default, native PPO/MAPPO append a fixed one-hot intersection id to actor and
value inputs:

```yaml
native_use_agent_id: True
```

This lets a shared MLP specialize behavior by intersection without using
HyperMARL-style generated weights. Disable it for a stricter parameter-sharing
baseline:

```yaml
native_use_agent_id: False
```

## Commands

```bash
python run.py --task tsc --agent ppo --world cityflow --network cityflow4x4 --prefix ppo_seed0 --seed 0 --ngpu 0
python run.py --task tsc --agent mappo --world cityflow --network cityflow4x4 --prefix mappo_seed0 --seed 0 --ngpu 0
```

Equivalent explicit aliases:

```bash
python run.py --task tsc --agent native_ppo --world cityflow --network cityflow4x4 --prefix native_ppo_seed0 --seed 0 --ngpu 0
python run.py --task tsc --agent native_mappo --world cityflow --network cityflow4x4 --prefix native_mappo_seed0 --seed 0 --ngpu 0
```
