HyperIRU 現行架構

一個遵循 CTDE 的交通號誌控制器：actor 以 IRU 在單次決策內重複計算， HyperLight learned intersection embedding 可選擇透過 FiLM 特化每個路口； centralized critic 保持原本的 HyperLight pooled value hypernetwork。

輸入、張量與 learned ID 路徑

1. Local state

每個路口 i 的 actor state 由進入車道的兩類特徵與目前 phase 組成：

sᵢ = concat([lane_countᵢ / vehicle_max, lane_waiting_countᵢ / vehicle_max], one_hot(phaseᵢ)) ∈ ℝᴰ
  • vehicle_max=50；不同路口的 lane feature 會 pad 到共同長度。
  • phase=True、one_hot=True；phase 維度取所有路口最大 action 數。
  • action mask 在 logits 上把不存在的 phase 設為 -1e9。

2. Learned intersection meta

每個路口另有可學習向量 eᵢ ∈ ℝ⁶⁴。它不會直接 append 到 sᵢ：

模式actor 看見什麼eᵢ 在 actor 的用途eᵢ 在 critic 的用途

FiLM IRU / filmsᵢ；另有 FiLM 條件生成 4H 個 γ/β生成 θᵛᵢ

命名注意：「FiLM IRU input = queue+phase+learned ID」容易誤解。較精確的寫法是：actor state 為 queue+phase，learned ID 是獨立 conditioning signal。

IRU 內部結構：單次決策內的 recurrent depth

數學定義

x = LN(Wᵢₙsᵢ + bᵢₙ)
FiLM(u; γ,β) = u ⊙ (1 + α tanh γ) + α tanh β，α = hyper_film_scale
zₜ = LN([x, hₜ₋₁]),　fₜ = σ(Wfzₜ + bf),　gₜ = tanh(Wgzₜ + bg)
mₜ = fₜ ⊙ mₜ₋₁ + (1 − fₜ) ⊙ gₜ,　h̃ₜ = tanh(mₜ),　hₜ = hₜ₋₁ + h̃ₜ

FiLM 模式在 input context 上套用一次 (γᶜ,βᶜ)，並在每個 thinking step 的 residual hidden 後套用同一組 (γʰ,βʰ)。

為什麼零初始化重要：actor hypernetwork 最後一層初始化為零，因此訓練開始時 FiLM IRU 與 Shared IRU 完全等價；模型先從共享策略開始，再逐步學習路口特化。

HyperLight-FiLM：路口特化而不生成整套 IRU

Shared IRU

hyper_adapter_mode=none

  • 所有路口共用同一個 IRU。
  • actor 不讀 learned ID。
  • 用來量測 IRU 架構本身的效果。

HyperLight-FiLM IRU

hyper_adapter_mode=film

  • IRU base weights 仍由所有路口共享。
  • 每個路口用 eᵢ 產生小型 activation adapter。
  • 用來量測路口特化是否與 recurrent computation 疊加。

Actor hypernetwork 的現行結構是 64 → 64 → 4H。對 H=64 而言輸出維度是 256，遠小於直接為 IRU 生成約 19.5k 個 base parameters。這是目前選擇 FiLM 而非 full generated IRU 的主要工程理由。

Centralized critic：保持 HyperLight MAPPO 路徑

hyperlight_mappo.yml 將 critic 設為 centralized_critic=True、centralized_critic_mode=pooled。對 batch 中所有路口狀態 S：

g(S) = concat(mean(S), std(S), max(S), min(S))
vᵢ = concat(sᵢ, g(S)) ∈ ℝ⁵ᴰ
θᵛᵢ = HyperValue(eᵢ),　Vᵢ = MLP(vᵢ; θᵛᵢ),　MLP widths = [5D, 128, 64, 1]
  • 每個路口的 learned embedding 生成自己的 value-network weights。
  • Shared IRU 和 FiLM IRU 使用完全相同的 critic，才能作 actor-only ablation。
  • 執行期選號誌 phase 不需要 global statistics 或 critic。
  • value_chunk_size=16 限制一次 materialize 的 generated critic weights，降低 peak memory。

PPO 訓練資料流

  1. 每 10 simulator seconds 做一次決策，actor 產生 masked categorical policy。
  2. rollout buffer 保存 raw state、next state、action、reward、done、old log-prob 和 old value。
  3. 累積 ppo_rollout_steps=360 後，使用 GAE 計算 advantage/return。
  4. 進行 4 個 PPO epochs；minibatch 上限為 2048 agent samples。
  5. 共同最佳化 policy loss、clipped value loss 與 entropy bonus。

參數量與計算深度

令 actor state 維度為 D、hidden size 為 H、action 數為 A、IRU block 數為 B。開啟 LayerNorm 時，共享 IRU base 約為：

PIRU = DH + AH + 4BH² + (3 + 6B)H + A

當 eᵢ=64、actor hyper hidden=64 時，FiLM actor hypernetwork 約 20,800 parameters。它產生的是 activation modulation，不是每個路口永久保存一份 IRU。

時間成本仍會增加：雖然 n1→n5 不增加 IRU 參數，recurrent loop 的 gate、LayerNorm 和 hidden update 會執行五次，因此 decision latency 與 PPO update time 仍近似隨 thinking steps 增加。

執行指令

Shared IRU n1

python -u run.py \
  --task tsc --agent hyperlight_mappo \
  --world cityflow --network cityflow16x3 \
  --prefix hyperlight_shared_iru1_seed0 --seed 0 --ngpu 0 \
  --agent_embedding_mode learned \
  --hyper_actor_arch iru --hyper_adapter_mode none \
  --iru_actor_steps 1 --iru_hidden_dim 64 --iru_num_blocks 1 \
  --hyper_residual False --episodes 250 --profile_performance True

HyperLight-FiLM IRU n1

python -u run.py \
  --task tsc --agent hyperlight_mappo \
  --world cityflow --network cityflow16x3 \
  --prefix hyperlight_film_iru1_seed0 --seed 0 --ngpu 0 \
  --agent_embedding_mode learned \
  --hyper_actor_arch iru --hyper_adapter_mode film --hyper_film_scale 0.1 \
  --iru_actor_steps 1 --iru_hidden_dim 64 --iru_num_blocks 1 \
  --hyper_residual False --episodes 250 --profile_performance True

將 seed 和 prefix 改成 1、2 即可完成三 seeds。FiLM 與 full/LoRA/head residual 是互斥路徑，因此這裡固定 hyper_residual=False。

目前邊界與限制

  • 沒有 full generated IRU：iru + generated 會主動拋錯，避免 hypernetwork 輸出過大的完整 recurrent weights。
  • 不是跨 timestep RNN：cell/hidden 每次 forward 都從零開始，不能直接表示跨號誌週期的 temporal memory。
  • FiLM 使用相同 hidden adapter：每個 thinking step 重用同一組 γʰ/βʰ；目前沒有 step-specific adapter。
  • 本文聚焦標準 HyperLight MAPPO：movement encoder、graph critic、CoS 等選項在此 16×3 2×2 實驗均關閉。
  • n5 尚非預設：現有 MAPPO-IRU 結果未顯示 n5 勝過 n1；應在 n1 的 FiLM 增益成立後再擴充。
